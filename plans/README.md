## Supported release matrix

| OS | Architecture | Primary artifacts |
|---|---|---|
| macOS 11+ | arm64 | DMG and ZIP |
| macOS 11+ | x64 | DMG and ZIP |
| Windows 10/11 | x64 | signed NSIS installer |
| Ubuntu 22.04/24.04 | x64 | AppImage and deb |

Windows ARM64, Linux ARM64, Flatpak, Snap, and a universal macOS artifact are
explicitly deferred. Separate macOS arm64 and x64 artifacts avoid the size cost
of a universal Electron application.

## Dependency notes

- Plan 001 is a decision gate. Do not implement Windows or Linux packaging until
  NDI binary availability, licensing, and redistribution are proven.
- Plan 002 prevents platform-specific NDI details from leaking through the main
  process and gives tests a fake provider.
- Plan 003 creates locally reproducible artifacts before CI is allowed to publish
  them.
- Plan 004 runs after packaged builds exist so integration tests exercise real
  platform behavior rather than assumptions.
- Plan 005 must publish all architecture artifacts in one coordinated release;
  matrix jobs must not independently create partial GitHub releases.
- Plan 006 is the release gate. A successful compile is not evidence that audio,
  NDI discovery, signing, or updates work on a target machine.

## Global constraints

- Use npm and commit `package-lock.json`; do not introduce Yarn or pnpm.
- Keep `nodeIntegration: false` and `contextIsolation: true`.
- Keep Node dependencies used by main/preload in `dependencies` because
  `externalizeDepsPlugin()` leaves them external at runtime.
- Build native modules separately on each target OS/architecture. Never copy a
  built `node_modules` directory between CI operating systems.
- Keep platform payloads target-specific. A Windows artifact must not contain
  macOS/Linux NDI runtimes, and vice versa.
- Do not change scripture lookup, transcription buffering, ProPresenter protocol,
  or renderer behavior as part of this migration.

## Deferred or rejected approaches

- Universal macOS build: rejected for now because it materially increases the
  Electron application and installer size. Publish separate x64 and arm64 builds.
- Build native addons on customer machines: rejected; releases must contain
  prebuilt and signed native modules.
- “All Linux distributions”: rejected as an unverifiable claim. The initial
  contract is Ubuntu 22.04/24.04 x64, with AppImage offered best-effort elsewhere.
- Retaining foreign NDI libraries in every installer: rejected because it wastes
  space and still does not make the native addon portable.
