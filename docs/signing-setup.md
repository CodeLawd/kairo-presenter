# Signing setup (secret names and procedure — never values)

Required for the `Release` workflow (`environment: release`). PR builds in
`CI` never receive these secrets and always build unsigned.

## Apple (macOS DMG + ZIP, hardened runtime + notarization)

| Secret | Value format |
|---|---|
| `CSC_LINK` | base64 of the Developer ID Application `.p12` |
| `CSC_KEY_PASSWORD` | `.p12` password |
| `APPLE_ID` | Apple ID email for notarization |
| `APPLE_APP_SPECIFIC_PASSWORD` | app-specific password for the Apple ID |
| `APPLE_TEAM_ID` | 10-character Team ID |

Procedure: export the Developer ID certificate from Keychain Access as
`.p12`, `base64` it into `CSC_LINK`, store the password in
`CSC_KEY_PASSWORD`, then add the notarization Apple ID triple. The existing
`build/entitlements.mac.plist` (JIT + disabled library validation for the
dlopened NDI runtime + mic/network) is applied automatically.

## Windows (NSIS installer)

| Secret | Value format |
|---|---|
| `WIN_CSC_LINK` | code-signing certificate (file path in repo or base64/URL as electron-builder supports) |
| `WIN_CSC_KEY_PASSWORD` | certificate password |

## Linux (AppImage + deb)

No signing identity: releases carry `sha256sums.txt` (generated by the
`publish` job) for verification.

## Repository settings

- Create a `release` environment; add all secrets there (never in code).
  Consider required reviewers on the environment so tags alone are not enough
  to spend signing identities.
- Protect `v*` tags (maintainers only) so the `Release` workflow cannot be
  triggered by untrusted pushes.
- Keep the `publish` job as the only `contents: write` step; matrix jobs stay
  read-only and upload to workflow storage instead of publishing.
- Rotate certificates outside source control; only secret metadata changes.
- Release workflow actions are pinned to immutable commit SHAs (see the
  `# v4` / `# v2` comments in `.github/workflows/`).
